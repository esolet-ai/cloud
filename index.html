01 — Overview

신입 운영 엔지니어의
입사 초기 업무를 기준으로 설계했습니다

참여기업 직무수요조사(20개 기업 응답)와 IT 인프라 분야 재직 수료생 13명의 초기 업무자료를 분석한 결과, 기업은 신입에게 단독 설계보다 설치·설정·점검·로그 확인·장애 대응 보조·운영문서 작성을 먼저 요구했습니다. 본 과정은 이 업무 흐름을 그대로 훈련 순서로 옮겼습니다.

서버·네트워크·저장소 구축 및 점검

Linux·Windows Server 설치와 설정, DNS·Web·DB 서비스 구성, VLAN·라우팅·방화벽·VPN, RAID·LVM 기반 저장소와 백업까지 운영환경의 바닥을 만드는 단계입니다.

현장 업무
기본 환경 구성 · 설치 · 설정 · 테스트
관련 교과
클라우드 운영 환경 구성 실무, Linux 서버 운영, 하이브리드 클라우드 네트워크

컨테이너 기반 배포 자동화

Docker 이미지로 서비스를 묶고, Kubernetes에 올리고, Ansible·Terraform으로 설치와 인프라 구성을 코드로 관리합니다. GitHub Actions·ArgoCD로 변경사항이 자동 반영되는 GitOps 배포까지 다룹니다.

현장 업무
배포 지원 → 결과 확인 → 문제 대응
관련 교과
인프라 운영 자동화, 컨테이너 오케스트레이션, GitOps 기반 배포 자동화, AWS 인프라 구축

로그·메트릭 기반 운영상태 확인

로그를 모으고(Fluentd·Logstash), 메트릭을 수집해(Prometheus) 대시보드(Grafana)로 봅니다. AI 서비스는 응답시간·지연·CPU·GPU 사용량까지 점검 대상에 포함합니다.

현장 업무
로그 확인 · 이상 여부 판단 · 자원 점검
관련 교과
로그 수집 및 메트릭 기반 운영 모니터링, LLM 서비스 모니터링

장애 원인 분석 및 복구

응답 지연, 배포 실패, 노드 장애, 컨테이너 재시작 상황을 일부러 만들어 원인을 추적하고 복구 절차를 수행합니다. 트래픽 제어(Istio), 카나리 배포, 고가용성(HA)·재해복구(DR) 구성을 함께 훈련합니다.

현장 업무
장애 접수 → 로그 확인 → 조치 보고
관련 교과
AI 서비스 트래픽 제어 및 고가용성 장애복구 실무, 2차 프로젝트

운영문서 작성 및 포트폴리오 정리

참여기업이 요구한 산출물 — 시스템 구성도, 구축 결과보고서, 장애 분석 보고서, 운영 매뉴얼, 점검표 — 를 프로젝트마다 작성하고, 이 문서를 면접에서 설명할 수 있는 직무 포트폴리오로 정리합니다.

현장 업무

관련 교과

기존 과정 재편

2년 운영 결과로 다시 설계

「KT클라우드와 NHN Cloud로 완성하는 클라우드 엔지니어 양성」(누적 양성 259명, 2025년 성과평가 B·증원)의 운영 결과를 분석해, 범용 인프라 교육을 클라우드 운영 중심으로 재편했습니다.

AI는 '운영 대상'

AI 모델 개발이 아닌, AI 서비스 운영

LLM·RAG 서비스는 클라우드 위에서 배포·모니터링·자원 점검·장애 대응이 필요한 운영 대상으로 다룹니다. 직종은 디지털 전략산업 분야 중 클라우드입니다.

보안은 '운영통제'

계정·접근권한·작업로그 관리

운영보안 수요는 별도 보안 과정이 아니라 클라우드 운영자가 매일 하는 계정관리, 접근권한 관리, 작업로그 확인으로 반영했습니다(HIWARE 실습).

03 — Project

핵심 프로젝트 2개와 고도화 구간

기존에 3개 내외로 나눠 하던 프로젝트를 핵심 프로젝트 2개로 압축했습니다. 결과물을 만든 뒤 고치고 문서화하는 시간이 부족했다는 운영 결과를 반영한 것입니다.

PROJECT 01 · 120H

Private Cloud Platform 구축

사내 업무서비스(전자결재, LMS, 헬프데스크 중 1개)를 프라이빗 클라우드에 올리고, 개발 협업과 컨테이너 배포 플랫폼을 구성합니다. 애플리케이션 기능 개발보다 Web·WAS·DB·저장소·네트워크 연동과 운영 검증에 초점을 둡니다.

팀 주제

  • 사내 업무서비스 운영 인프라 구축 — 서비스 접근 흐름, 백업·복구, 장애 대응 절차 수행
  • 개발 협업 및 컨테이너 배포 플랫폼 구축 — Git·Harbor, Docker 배포, Ansible 자동화

산출물

시스템 구성도구축 결과보고서운영 절차서장애 분석 보고서백업·복구 검증 자료

PROJECT 02 · 200H

하이브리드 클라우드 기반 AI 서비스 호스팅 및 통합 관제 아키텍처 구축

1차에서 만든 프라이빗 환경을 AWS와 연결하고, LLM·RAG 서비스를 운영 대상으로 배포합니다. 트래픽 증가, 응답 지연, 배포 실패, 자원 부족 상황을 가정해 원인 확인과 복구 결과를 기록합니다.

팀 주제

  • 하이브리드 클라우드 기반 AI 서비스 호스팅 아키텍처 구축
  • Kubernetes 기반 AI 서비스 배포 및 GitOps 자동화 구성
  • AI 서비스 운영상태 모니터링 및 장애 대응 체계 구축
  • AI 서비스 트래픽 제어 및 고가용성 복구 환경 구축
구축·배포·운영 검증 160H고도화 40H

산출물

아키텍처 구성도배포 절차서·롤백 기록운영 대시보드장애 분석 보고서복구 절차서개선 결과보고서

팀 구성팀당 3~6명. PM·인프라·배포자동화·모니터링·장애대응·문서화 역할을 학습수준과 희망직무를 고려해 배정
점검 시점사전 기획 보고(착수 후 10% 이내) → 중간점검(50% 내외) → 최종발표(종료 전)
현업 참여참여기업 멘토가 요구사항·기술구성·산출물을 단계별로 검토. ㈜에스엠인포메이션 제공 RFP를 비식별화해 과업 설계에 활용
평가전담 교강사 주관, 참여기업 멘토·기술자문위원·동료평가 의견 반영. 기술구현, 실무 적용성, 문제해결 과정, 협업, 문서화, 발표 및 질의응답

04 — After Training

수료 후 수행 업무와 취업 직무

"무엇을 배웠는가"보다 "입사 첫 달에 무엇을 할 수 있는가"를 기준으로 정리했습니다. 훈련목표 수준은 NCS 5수준입니다.

수행 가능 업무

  1. 설치 → 설정 → 테스트고객사·사내 환경에 서버, 네트워크, 솔루션을 설치하고 정상 동작을 확인
  2. 배포 지원 → 결과 확인 → 문제 대응컨테이너 이미지를 Kubernetes·EKS에 배포하고 GitOps로 변경·롤백
  3. 장애 접수 → 로그 확인 → 조치 보고로그·메트릭으로 장애 구간을 찾고 조치 결과를 보고서로 작성
  4. AI 서비스 운영 점검LLM 서비스 응답시간, CPU·GPU 자원, 트래픽을 확인하고 고가용성 구성 유지
  5. 운영통제계정·접근권한·작업로그를 관리하고 감사 대응 자료 준비

07 — Glossary

과정 주요 용어 설명

과정 안내와 커리큘럼에 나오는 용어를 비전공자 기준으로 풀었습니다. 각 용어 아래에 어느 교과에서 배우는지 표시했습니다.

0개 용어

하이브리드 클라우드 Hybrid Cloud
회사 내부의 프라이빗 클라우드와 AWS 같은 퍼블릭 클라우드를 네트워크로 연결해 하나의 운영환경처럼 쓰는 방식. 중요한 데이터는 내부에, 확장이 필요한 서비스는 외부에 두는 식으로 나눠 운영합니다.하이브리드 클라우드 네트워크 · 2차 프로젝트
프라이빗 클라우드 Private Cloud
기업이 자체 서버와 데이터센터에 구축해 단독으로 사용하는 클라우드 환경. 가상화 소프트웨어로 서버 자원을 나눠 필요한 부서·서비스에 배정합니다.프라이빗 클라우드 플랫폼 구축 · 1차 프로젝트
퍼블릭 클라우드 Public Cloud
AWS처럼 클라우드 사업자가 제공하는 서버·저장소·네트워크를 인터넷으로 빌려 쓰고 사용한 만큼 비용을 내는 방식.AWS 클라우드 인프라 구축
가상화 ESXi · vSphere
물리 서버 한 대를 여러 대의 가상 서버(VM)로 나눠 쓰는 기술. ESXi는 서버에 설치하는 가상화 소프트웨어, vSphere·vCenter는 여러 ESXi 서버를 한곳에서 관리하는 도구입니다.프라이빗 클라우드 플랫폼 구축
VLAN · 라우팅 VLAN · Routing
VLAN은 스위치 하나에서 네트워크를 논리적으로 나누는 기술이고, 라우팅은 서로 다른 네트워크 사이에서 데이터가 갈 길을 정하는 기술입니다. 서비스망·관리망 분리의 기본입니다.하이브리드 클라우드 네트워크 구축 및 운영
VPN Virtual Private Network
인터넷 위에 암호화된 전용 통로를 만들어 떨어진 두 네트워크를 안전하게 연결하는 기술. 하이브리드 클라우드에서 사내망과 AWS를 잇는 데 씁니다.하이브리드 클라우드 네트워크 구축 및 운영
로드밸런서 HAProxy · ALB
들어오는 요청을 여러 서버에 나눠 보내 한 서버에 부하가 몰리지 않게 하는 장치·소프트웨어. 서버 하나가 멈춰도 다른 서버로 요청을 돌릴 수 있습니다.네트워크 · AWS · 2차 프로젝트
RAID · LVM · NFS Storage
RAID는 여러 디스크를 묶어 속도나 안정성을 높이는 방식, LVM은 디스크 용량을 유연하게 늘리고 줄이는 관리 방식, NFS는 네트워크로 저장소를 공유하는 방식입니다.데이터 저장소 및 백업 운영
VPC Virtual Private Cloud
AWS 안에 나만의 격리된 네트워크 공간을 만드는 기능. 서브넷, 보안그룹, 라우팅을 설정해 서비스가 놓일 자리를 설계합니다.AWS 클라우드 인프라 구축
IAM · RBAC 권한 관리
누가 어떤 자원에 어떤 작업을 할 수 있는지 정하는 권한 체계. IAM은 AWS의 권한 관리, RBAC는 역할(Role) 단위로 권한을 주는 방식으로 Kubernetes에서도 씁니다.AWS · 컨테이너 오케스트레이션
컨테이너 · Docker Container
애플리케이션과 실행에 필요한 설정·라이브러리를 하나의 상자(이미지)로 묶어 어디서든 똑같이 실행되게 하는 기술. Docker는 가장 널리 쓰이는 컨테이너 도구입니다.컨테이너 오케스트레이션 · 1차 프로젝트
Kubernetes k8s
수많은 컨테이너를 여러 서버에 배치하고, 멈추면 다시 띄우고, 부하에 따라 늘리고 줄이는 일을 자동으로 관리하는 플랫폼. 클라우드 운영 직무의 핵심 기술입니다.컨테이너 오케스트레이션 플랫폼 운영
EKS Amazon Elastic Kubernetes Service
AWS가 관리해 주는 Kubernetes 서비스. 클러스터의 핵심 관리 부분을 AWS가 맡아 운영자는 서비스 배포와 운영에 집중합니다.AWS 클라우드 인프라 구축 · 2차 프로젝트
컨테이너 레지스트리 Harbor
만든 컨테이너 이미지를 저장하고 버전별로 관리하는 저장소. Harbor는 기업이 사내에 직접 설치해 쓰는 레지스트리입니다.GitOps 배포 자동화 · 1차 프로젝트
IaC Infrastructure as Code
서버·네트워크 구성을 사람이 손으로 설정하지 않고 코드로 작성해 자동으로 만드는 방식. 같은 환경을 실수 없이 반복해 만들 수 있습니다.인프라 운영 자동화 · AWS
Ansible Configuration Management
여러 서버에 같은 설치·설정 작업을 한 번에 자동으로 실행하는 도구. 작업 내용을 문서처럼 읽히는 파일(플레이북)로 작성합니다.인프라 운영 자동화 실무 · 1차 프로젝트
Terraform IaC Tool
클라우드 자원(VPC, 서버, 로드밸런서 등)을 코드로 정의하고 생성·변경·삭제하는 도구.AWS 클라우드 인프라 구축
CI/CD Continuous Integration / Delivery
코드가 바뀌면 자동으로 빌드·테스트(CI)하고 운영환경까지 배포(CD)하는 흐름. GitHub Actions가 대표 도구입니다.GitOps 기반 AI 서비스 운영환경 배포 자동화
GitOps · ArgoCD GitOps
운영환경의 '원하는 상태'를 Git 저장소에 기록해 두고, 도구(ArgoCD)가 실제 환경을 그 상태와 자동으로 맞추는 배포 방식. 변경 이력이 남고 이전 상태로 되돌리기(롤백) 쉽습니다.GitOps 배포 자동화 · 2차 프로젝트
DevOps Development + Operations
개발과 운영을 분리하지 않고 배포 자동화, 모니터링, 빠른 개선을 함께 운영하는 방식과 문화. 본 과정에서는 DevOps 중 '운영' 업무에 초점을 둡니다.과정 전반
로그 · 메트릭 Log · Metric
로그는 시스템이 남기는 사건 기록(언제 어떤 오류가 났는지), 메트릭은 숫자로 측정한 상태(CPU 사용률, 응답시간 등)입니다. 장애 원인을 찾는 출발점입니다.로그 수집 및 메트릭 기반 운영 모니터링
Prometheus · Grafana Monitoring
Prometheus는 메트릭을 주기적으로 수집·저장하는 도구, Grafana는 수집한 데이터를 대시보드와 그래프로 보여주는 도구입니다. 알림 설정도 함께 다룹니다.컨테이너 오케스트레이션 · LLM 서비스 모니터링
Fluentd · Logstash Log Pipeline
여러 서버와 컨테이너에 흩어진 로그를 한곳으로 모으고 정리하는 수집 도구.클라우드 인프라 로그 수집
고가용성 · 재해복구 HA · DR
고가용성(HA)은 일부 장비가 고장 나도 서비스가 멈추지 않게 이중화하는 구성, 재해복구(DR)는 큰 장애가 났을 때 다른 위치에서 서비스를 되살리는 체계입니다.AI 서비스 트래픽 제어 및 고가용성 장애복구 실무
카나리 배포 · 롤링 업데이트 Deployment Strategy
새 버전을 한 번에 바꾸지 않는 배포 방식. 카나리 배포는 일부 사용자에게만 먼저 적용해 문제를 확인하고, 롤링 업데이트는 서버를 하나씩 순서대로 교체합니다.AI 서비스 트래픽 제어 · 2차 프로젝트
서비스 메시 Istio
서비스 사이의 통신을 별도 계층에서 관리해 트래픽 분배, 재시도, 장애 격리, 통신 상태 확인을 할 수 있게 하는 구조. Istio가 대표 도구입니다.AI 서비스 트래픽 제어 및 고가용성 장애복구 실무
오토스케일링 Auto Scaling
접속이 몰리면 서버나 컨테이너 수를 자동으로 늘리고, 줄어들면 다시 줄이는 기능. 비용과 안정성을 함께 관리합니다.AWS · 2차 프로젝트
접근권한 관리 · 작업로그 HIWARE
운영자가 서버·DB·네트워크 장비에 접속할 때 누가, 언제, 무엇을 했는지 통제하고 기록하는 일. 감사 대응의 근거가 됩니다. HIWARE는 ㈜넷앤드의 접근통제 솔루션입니다.운영통제 실습 · 2차 프로젝트
트러블슈팅 · 장애 분석 보고서 Troubleshooting
장애의 현상, 원인, 조치, 재발 방지 대책을 기록한 문서. 신입 운영 엔지니어가 가장 자주 작성하는 문서 중 하나입니다.1·2차 프로젝트 산출물
LLM Large Language Model
대량의 텍스트로 학습해 질문에 답하고 글을 생성하는 AI 모델. 본 과정에서는 모델을 만드는 것이 아니라, LLM 서비스를 클라우드에 배포하고 안정적으로 운영하는 방법을 배웁니다.GitOps 배포 자동화 · LLM 서비스 모니터링
RAG Retrieval-Augmented Generation
AI가 답변하기 전에 회사 문서 같은 외부 자료를 먼저 검색해 참고하도록 만든 서비스 구조. 검색 저장소, AI 모델, 서비스가 함께 움직여 운영 대상이 많아집니다.2차 프로젝트 운영 대상
Ollama Local LLM Runtime
LLM을 외부 서비스가 아닌 내 서버나 컨테이너에서 직접 실행할 수 있게 해 주는 도구. 사내 환경 AI 서비스 배포 실습에 씁니다.GitOps 기반 AI 서비스 운영환경 배포 자동화
AI API · 응답 지연 Latency

09 — FAQ

자주 묻는 질문

비전공자도 따라갈 수 있나요?

입과 초기에 Linux·네트워크·클라우드 기초역량을 진단하고, 부족한 부분은 STEP 콘텐츠, 질의응답, 스터디 그룹, 보충학습으로 보완합니다. 과정 초반 336시간을 운영 기반 교과로 편성한 것도 학습속도 차이를 줄이기 위해서입니다. 다만 6개월 장기훈련이므로 학습의지와 출결 유지가 중요합니다.

AI 개발자가 되는 과정인가요?

아닙니다. 이 과정은 AI 모델을 만드는 과정이 아니라, AI 서비스가 클라우드 위에서 멈추지 않고 돌아가도록 배포·모니터링·자원 점검·장애 대응을 하는 클라우드 운영 엔지니어 과정입니다. AI 서비스는 '운영 대상'으로 다룹니다.

보안 과정과는 무엇이 다른가요?

별도의 보안 전문과정은 아닙니다. HIWARE와 같은 접근통제 솔루션을 활용해 계정·접근권한·작업로그를 관리하며 클라우드 운영 보안을 확인합니다.

미리 공부해 두면 좋은 것이 있나요?

Linux 기본 명령어, IP 주소와 네트워크 기초, 컴퓨터 구조 기초를 미리 보면 초반 적응에 도움이 됩니다. 위의 용어 사전으로 과정에서 쓰는 단어를 먼저 익혀 두는 것도 좋습니다.

프로젝트는 어떻게 진행되나요?

3~6명이 한 팀이 되어 1차(120H), 2차(200H) 프로젝트를 수행합니다. 사전 기획 보고, 중간점검, 최종발표 단계마다 교강사와 참여기업 멘토가 피드백하고, 2차 프로젝트의 마지막 40시간은 결과물 보완과 문서화, 포트폴리오 정리에 씁니다.

수료 후에도 취업지원을 받을 수 있나요?

수료 후 6개월간 사후관리를 합니다. 주간 취업회의에서 훈련생별 지원현황과 미취업 사유를 점검하고, 추가 상담, 이력서·포트폴리오 보완, 모의면접, 참여기업과 기존 취업처 재매칭을 진행합니다.

훈련비 지원은 어떻게 되나요?

K-디지털 트레이닝 과정으로 국민내일배움카드를 사용합니다. 세부 지원 조건은 홈페이지 상담 신청 또는 카카오톡 상담으로 안내합니다.
